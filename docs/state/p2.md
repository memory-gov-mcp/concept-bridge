## 当前状态（2026-11-02）

P0 卡 T1–T5 已用 `--no-ff` 合入 `main` 并推送。GitHub Actions 的 `check`（`uv run task check` + `uv run task e2e`）在这些推送上通过。

`match/pipeline.py` 的 `run_bridge()` 已存在。未开 `DEMO_MODE` 时，`/api/v1/bridge` 走这套实现，`meta.stub=false`。语料仍是 `fixtures/bridge.sample.json`（源侧 2 条 + 目标侧 2 条）。三条演示 query 都能返回跨域桥。超时预算用尽时保留已生成的桥并标 `degraded=true`；内部异常返回空桥，不把样例桥填进这次结果。

评测在 30 条金标准正例闭集上算出，报告在 `eval/reports/latest.md`：

| 配置 | P@5 | MRR@10 |
|---|---|---|
| A 纯语义 | 0.7667 | 0.3848 |
| B 加结构签名 | 1.0000 | 0.9611 |
| C 再加领域距离 | 1.0000 | 0.9611 |
| D 完整 | 1.0000 | 0.9611 |

闭集里的目标全部跨 field，`domain_dist` 恒为 1，所以 B 和 C 的排序相同。重排只在 LLM 缓存命中时改写文案，不改分数，所以没有缓存时 D 和 C 相同。这不是 1500 篇文献库上的数字。

T6 多步子图匹配已落地：概念节点超过 8 个就退回单条机制，以内同构走 VF2，否则用类型与动作的排序差。在线 `run_bridge` 仍按单条机制打分。T7 已记下 10 条负例的误报率：关掉反琐碎是 0.4000，完整公式是 0.0000。这 10 条都跨 field，领域距离和正例一样是 1，下降来自反琐碎。要在真实机制上建图、调参，等 P1 的 `fixtures/mechanisms.min.jsonl`（卡 P1-T4，目前仍是 todo）。
